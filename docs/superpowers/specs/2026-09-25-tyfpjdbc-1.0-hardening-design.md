# TyFPJDBC 1.0 生产级加固规格（production hardening）

版本：0.1（brainstorming 已确认三节，待评审后转 implementation plan）
日期：2026-09-25
基线：master `db194dd`（version 0.9.0，无 v2 后缀命名）
目标：1.0 完美版本，架构与内核允许随意修改（0.x 特权）。

## 0. 约束（已确认）

- 真库优先级：H2 / SQLite / PG / MySQL。MSSQL / Oracle 保持方言形状断言，不建真库。
- 负载：小服务端、长稳运行。
- 稳定性排序：可观测优先，其次故障可恢复，最后长稳零泄漏（都要做，先后有别）。
- 易用性：代码 API 与 DB 控件同等主力，共用配置、错误、观测。
- 为什么 JDBC 封装了还要测真库：JDBC 只统一接口形状，不统一语义。
  分页/引用/自增/类型、取消与超时的真假、回填形状、隔离语义、错误码、
  大小写折叠、驱动版本坑都会漏出来，必须逐库标定基线。

## 1. 总体架构（已确认）

- 单一状态机不变：Java `Bridge` 唯一持有池/连接/语句/游标，
  Pascal 只拿 `Int64` 句柄；`TJdbcEngine` 只做校验与计数，不缓存业务状态。
- 新增统一内核三件套：
  - `TJdbcConfig`：JVM / 池 / 执行 / 观测唯一入口，
    LCL 属性编辑器、mautool、代码三方共用同一份。
  - `TJdbcError`：typed 分类（可重试 / 不可重试 / 配置错 / 驱动原生），
    携带 `SQLState` + 驱动码 + 恢复建议。
  - `TLifecycle`：游标 → 语句 → 连接 → 池 → JVM 逆序释放规范 + 句柄审计。
- 分层测试金字塔：纯逻辑（毫秒级）→ 真库语义（容器矩阵）→
  长稳（soak + 故障注入 + tiers 性能基线），每层独立通过标准。
- 双主力入口：`TJdbcCommand` / `TJdbcQuery`（代码）与
  `TJdbcConnQuery`（LCL）共用同一配置、同一错误、同一观测，
  不再各自定义默认值。

## 2. 测试覆盖（已确认）

- 注入：hostile 矩阵（引号、分号、注释、转义、宽字节、CJK）逐库验证
  入库后原样读回且表结构存活；`RewriteNamedParams` 加 fuzz 属性测试，
  断言 `?` 数量恒等于绑定数。
- 事务：单连接 savepoint 部分回滚、多语句原子提交/回滚、
  双连接并发读写同一行（按隔离级别行为基线化）、死锁/超时归类为可重试。
  PG / MySQL 与 H2 / SQLite 差异记录为基线，不强求一致。
- 多连接：池打满策略（等待 vs 立刻失败可配）、借还配对审计、
  泄漏检测阈值联动、可选借出前 `IsValid` 探活。
- 高并发：soak 参数化（线程数 × 迭代数 × 混合读写比），
  断言零错位、句柄归零、`AttachedCount` 回基线，外加取消与超时交叉压力。
- 性能：保留现有 tiers / PerfCompare workload 与 checksum 对齐，
  新增 P95 延迟与内存水位（FPC 堆 + Java 堆）；
  只卡“不回归 + 无泄漏”，不卡绝对毫秒数。

## 3. 配置收口、稳定性、易用性（已确认）

- 配置收口：`TJdbcConfig` 分组为 JVM / 池 / 执行 / 观测；
  所有默认值集中一处、有范围校验；三方只读这一份。
  现状分散硬编码全部具名化并写清来源：
  `Xmx 512m`、`MaxRAM% 60`、强制 `UTF-8` / `headless`（默认锁定、
  显式解锁告警）、慢阈值 `1000ms`、窗口 `1000`、批量上限 `10000`、
  宽串建表宽 `255`、savepoint 名 `64` 字符白名单、池默认 `10/2/30s` 等。
- 稳定性（可观测优先）：慢查询分级、池快照可拉取、错误链结构化、
  句柄审计；可重试与不可重试分开；池满策略可配且有超时；
  soak 常态化，句柄与内存双归零才算过。
- 易用性：代码侧一次 `OpenPool` 走完全程，错误信息带修复建议；
  控件侧连接只存配置、查询只存 SQL + 键 + 窗口，行为与代码侧逐项对齐；
  `DRIVER` / `DIALECT-MATRIX` / `TROUBLESHOOTING` 按 1.0 重写，
  每个配置项写清默认值、范围、影响。

## 4. 非目标

- 不新增 MSSQL / Oracle 真库，不做 benchmark 竞赛式优化。
- 不改 `Bridge` JNI 扁平签名形状（`createPoolFlat` 保持兼容），
  内核重构只动 Pascal 侧组织与分类。
- 不做与生产加固无关的构建链重写。

## 5. 验收（转 plan 时细化）

- `scripts/guard.ps1` 全绿（含源码旁产物门禁）。
- `scripts/run-matrix.ps1` 全绿：纯逻辑 + 4 真库语义 + soak +
  故障注入 + tiers + examples + lpk。
- 证据：tests / launch / guard / matrix 四份日志归档，
  PG / MySQL 无库时记 `SKIP` 环境缺失，不伪造成功。
